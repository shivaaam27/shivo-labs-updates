# Shivo Labs hub (laptop)

The one Shivo Labs app on Windows, laid out like the phone app: splash, a welcome screen the first time, then a home of module cards. Shivo Labs AI, Beam and X Tools are modules. None of them is the hub.

- `modules.json` lists the modules. **To add a module, add one entry**: `id`, `name`, `sub` (the short line under the name), `icon` (svg paths) or `"mark": true`, `check` (a file that exists once it is installed), `start` (the command that opens it), and `port` (optional, shows "Open" while it runs).
- `server.mjs` is a small local server on port 4800 that uses only Node's built-in modules. It serves `www/` and `../shared/`, reports module status, and starts a module when its card is clicked. It only answers this PC.
- `www/` holds the page. Its look comes from `../shared/tokens.css`, the same colours, fonts, glass and cards as `phone/www/app.css`.

Run it from the repo root: `node hub\server.mjs`, then open http://localhost:4800.

Desktop shortcut "Shivo Labs" runs `Shivo Labs.vbs`, which starts the server (if it isn't running) and opens an Edge app window.

**Module pages.** A module with `"page": true` opens inside the hub. Its screen is `www/modules/<id>.js` (registered in `PAGES` in `www/hub.js`), and its server side, if it has one, is `api/<id>.mjs`. Every request that changes something must send the header `x-hub: 1`.
- **Beam** has a page and its own engine: `engines/beam_host.py` runs `beam/app/beam/beam.py` from this repo (no tray app), in a private Python environment `%LOCALAPPDATA%\Shivo Labs\beam-env` (zeroconf for beam.local). The hub starts it and restarts it if it stops (only the real hub on port 4800). "Accept files from an iPhone?" is asked through `/api/beam/ask` and shown on any hub screen; if no hub window is open, the hub opens one. Settings and trusted iPhones stay in `%APPDATA%\Beam`.
- **X Tools** has a page. `api/xtools-bridge.ps1` runs the X Tools engine (`Engine.ps1`, copied from `x-tools/installer/src` into `%LOCALAPPDATA%\Shivo Labs\xtools-engine` each time it starts; no self-updater) in a hidden PowerShell (commands in on stdin, replies and events out on stdout, as JSON lines), and `api/xtools.mjs` passes the page's commands to it and streams progress and the Apple 2FA question as events. It shares the lock with the old X Tools window (only one runs at a time) and lets go when you leave the page. The Apple password only passes through; it is never stored or logged. X Tools data stays in `%LOCALAPPDATA%\Fabra Labs` and the WSL distro `FabraLabs`.
- **Chat** has a page: `../shared/chat/chat.js` (the same screen the phone will use). It talks straight to the Shivo Labs Chat server on Cloudflare, not to this hub server. See `chat/README.md`.
- **Mirror** shows the iPhone's screen, wirelessly (Control Center > Screen Mirroring > "Shivo Labs"), any iOS version. The AirPlay receiver is plain JavaScript in the hub (`api/airplay/`: `receiver.mjs` protocol, `mdns.mjs` discovery, `bplist.mjs` Apple plists, `playfair.mjs` FairPlay key unwrap ported from UxPlay, GPL-3.0), so Smart App Control has no extra program to block. Ports TCP 7000 and 7100, UDP 7011, 6000, 6001 and 5353; the receiver key is in `%LOCALAPPDATA%\Shivo Labs\mirror`. `api/mirror.mjs` sends frames to the page, which decodes them with WebCodecs. It tells the phone it has a 1920x1920 screen (`HUB_MIRROR_SIZE` to change), so an upright iPhone arrives 886x1920. When a phone connects the picture opens by itself in a floating window (`engines/mirror-window.ps1`: Windows PowerShell + Microsoft's signed WebView2 files from the NuGet cache, or `..wv2` in an install; always on top, phone-shaped, no browser frame), showing `www/mirror-float.html`; the player is `www/modules/mirror-player.js` (decodes on the processor: the graphics chip held ~3 pictures back). Only the hub on 4800 starts it; the preview copy is launch config "hub-mirror-dev" (`HUB_MIRROR_NAME`, `HUB_MIRROR_PORTS`: a second receiver "Shivo Labs Dev" on other ports). Lag on this PC came from Wi-Fi power saving (ping to the phone up to 1.2 s), not the hub. Sound is not played yet. The CI check `airplay-check.yml` compares `playfair.mjs` with UxPlay's C code.
- **Shivo Labs AI** opens inside the hub window, full size (`www/modules/ai.js`, `"full": true`). The hub starts only its server (`"server"`: `launcher.mjs` in `Documents\Shivo Labs AI\fabra-labs-ai`, which keeps its own updater) and shows `http://localhost:4823` in a frame that stays loaded while you are elsewhere in the hub. The hub window uses the AI app's Edge profile (`~\.fabra-labs-ai\edge`), because the chats are saved there. From 2.0.0 the AI page knows it is in the hub (it checks the hub's address) and shows a home button at the top of its rail; older versions get a small home button from the hub (bottom right). Test copies: `HUB_AI_PORT` / `HUB_AI_EMBED` point the hub at the AI test copy (launch config "hub-with-ai-dev").

- **TV** has a page (`www/modules/tv.js`, `api/tv.mjs`): Android TV and Google TV sets on the same Wi-Fi. It finds them by SSDP (DIAL, like a phone finding a Chromecast) and checks Google's TV remote ports 6466/6467, and talks to them with Google's **adb** over Wi-Fi: downloaded from dl.google.com the first time into `%LOCALAPPDATA%\Shivo Labs\tv\platform-tools` and kept only if Windows says it is signed by Google LLC (here it also uses `~\.fabra-labs-ai\android-build\platform-tools`). The TV needs Developer options on once: **Wireless debugging** on Google TV and newer TVs (the hub finds its changing port by mDNS, `_adb-tls-connect._tcp`, and pairs with the 6-digit code the TV shows), or **USB debugging** on older ones (port 5555). Then: put the Shivo Labs home screen on the TV (`tv/home`, carried by the installer in `tv\`), make it the home screen (the stock launchers are switched off with `pm disable-user`, never removed; "Bring back" switches them on), list every app (names and icons come from the home screen app's `Export` receiver, which only adb can call), open, switch off / on (system apps that can't be opened, and a keep-list, are never offered) and uninstall (apps the user added), and a remote (keys over one long-lived `adb shell`, typing, a picture of the TV screen every 3 s). Remembered TVs: `%LOCALAPPDATA%\Shivo Labs\tv\tvs.json`. Updates of the home screen app reach installed PCs only with a new installer for now (the hub update carries `hub/` and `shared/` only).

**Installing on another PC:** the one installer, `installer/` at the repo root (`installer/README.md`). `%ROOT%` in `modules.json` is the folder that holds `hub\` (this repo here, the program folder when installed) and `%NODE%` its Node.js; `"dir"` lists where a module's program may be, first one that exists wins.

**Switching a PC to the hub:** double-click `setup\Switch to the Shivo Labs hub.cmd` once. It removes the standalone Beam and X Tools and the old shortcuts (keeping their data), sets up Beam's engine, and adds "Shivo Labs" to the Desktop, Start menu, start-with-Windows (quietly, `/background`) and Explorer Send to > iPhone (Beam). It has to run outside Claude: the Claude desktop app redirects writes to AppData into its own sandbox.

**Settings** (gear on the home screen; `www/modules/settings.js`, `api/settings.mjs`): updates, theme (light / dark / automatic), start with Windows, the apps and their state, "Shivo Labs AI settings" (asks the AI page inside the hub to open its own Settings), where each app keeps its data, restart.

**Updates** (`api/update.mjs`; the gear shows a dot when one is ready; checked 30 s after start and every 6 h, only by the real hub on 4800):
- *Repo* (this folder is a git checkout, Shivam's PC): compares with `origin/main`; Install runs `git pull --rebase origin main` (refused if tracked files have changes) and restarts the hub server.
- *Installed*: over the air, like the phone app. `.github/workflows/hub-ota.yml` publishes every change to folder `hub/` of the public repo `shivaaam27/shivo-labs-updates` (the files, and `manifest.json` with each file's SHA-256, signed; `update-key.xml` is the public half). Every 15 minutes `api/update.mjs` checks (pinned to one commit of that repo), downloads only the files that differ, verifies each, backs up, installs by itself and restarts only what changed: the hub server through `engines/restart.mjs` (which puts the backup back if the hub doesn't answer); the AI server and Beam's engine are stopped and the hub starts them again. See `installer/README.md`.
- Never installs while Shivo Labs AI has a chat or scheduled task working (its `/api/update` says `busy`). User data is outside the program folder, so updates don't touch it.
